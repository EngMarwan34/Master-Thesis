# نظام تقارير الصيانة الوقائية (PPM) — شركة المحتسب

تطبيق ويب بصفحة واحدة (`index.html`) بلا خطوة بناء، يستخدم **Supabase** كقاعدة
بيانات ومصادقة وتخزين، وينشر عبر **Netlify Drop** بنفس أسلوب أنظمتك السابقة.
يطابق الملفان `index.html` و `sql/schema.sql` المواصفة الكاملة المرسلة
(الأدوار، مخطط قاعدة البيانات، تدفق العمل، التقرير ثنائي اللغة، لوحة المتابعة،
ملصقات QR).

## محتويات المجلد
```
ppm-system/
├── index.html        ← التطبيق كاملاً (الواجهة + منطق الاتصال بـ Supabase)
├── sql/schema.sql     ← الجداول + سياسات RLS + الدوال + Storage Bucket
└── README.md          ← هذا الملف
```

## خطوات التشغيل (مرة واحدة)

### ١. إنشاء مشروع Supabase
1. أنشئ حساباً/مشروعاً مجانياً على [supabase.com](https://supabase.com).
2. من **SQL Editor** داخل المشروع، الصق محتوى `sql/schema.sql` كاملاً واضغط
   **Run**. هذا ينشئ الجداول، الأنواع، الدوال، سياسات RLS، وحاوية تخزين
   الصور `ppm-photos` تلقائياً.
3. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`

### ٢. ربط الواجهة بالمشروع
افتح `index.html` وعدّل أعلى قسم `<script>`:
```js
const SUPABASE_URL = 'https://YOUR-PROJECT.supabase.co';
const SUPABASE_ANON_KEY = 'YOUR-ANON-PUBLIC-KEY';
const COMPANY_LOGO_URL = ''; // رابط شعار الشركة إن رغبت
```
مفتاح `anon` آمن للاستخدام داخل المتصفح — الحماية الفعلية بين الفروع
والعملاء مطبَّقة في قاعدة البيانات نفسها عبر RLS، وليست في الواجهة.

### ٣. إنشاء أول حساب "مشرف فرع"
1. من لوحة Supabase: **Authentication → Add user** — أدخل بريده وكلمة مرور.
2. في **SQL Editor** نفّذ مرة واحدة (استبدل القيم):
```sql
update public.profiles
set role = 'branch_admin', branch = 'اسم الفرع', full_name = 'اسم المشرف', active = true
where id = '<UUID المستخدم من صفحة Authentication>';
```
3. سجّل الدخول بهذا الحساب من `index.html` — ستظهر لوحة المتابعة.

### ٤. إنشاء حسابات الفنيين والعملاء
- **فني/عميل جديد:** أضفه من **Authentication → Add user** بنفس الطريقة،
  ثم من داخل النظام (حساب مشرف الفرع) → **إدارة المستخدمين** → عدّل اسمه،
  دوره (فني ميداني/عميل اطلاع)، فرعه، وإن كان "عميل" اربطه بسجل العميل
  المطابق. لا حاجة لأي كود أو Edge Function.

### ٥. النشر
اسحب مجلد `ppm-system` (أو ملف `index.html` فقط) وأفلته في
[app.netlify.com/drop](https://app.netlify.com/drop) — تماماً كما فعلت في
أنظمتك السابقة. النشر مجاني، ويبقى كذلك مهما زاد عدد الزيارات لأن كل
التخزين الفعلي (البيانات والصور) في Supabase لا في Netlify.

## تدفّق الاستخدام السريع
1. **المكتب (مشرف الفرع):** العملاء ← أضف عميلاً ← استيراد Excel لأجهزته
   (مطابقة أعمدة تفاعلية) ← إنشاء عقد ← طباعة ملصقات QR (A4، قابلة للقص).
2. **الفني (جوال):** تسجيل الدخول ← عملائي ← بدء زيارة ← مسح QR أو اختيار
   من القائمة ← تُعرض بطاقة الجهاز مع صورته المرجعية وسجله السابق كاملاً
   (مع تنبيه تكرار العطل) ← اختيار الحالة من الحالات الخمس ← صورة عامة
   إلزامية، وصورة عيب + نص القطع المطلوبة إن لم يكن سليماً ← يمكن إضافة
   جهاز غير مسجَّل ← شريط تقدم حي ← إنهاء الزيارة (تُقفل للفني فوراً).
3. **المكتب (اعتماد):** الاعتمادات ← مراجعة كل بند وصوره، تعديل الصياغة
   عند الحاجة ← اعتماد (يُصدر رقم تقرير تلقائياً ويظهر عندها فقط للعميل)
   أو رفض مع سبب يعود للفني لتعديله.
4. **التقرير:** ترويسة + بطاقات إحصائية + جدول ثنائي اللغة (عربي/إنجليزي
   جنباً إلى جنب) + توصيات + توقيعان. أزرار: طباعة/PDF عبر المتصفح، تصدير
   Excel لقطع الغيار المطلوبة فقط، ورابط مشاركة عام (واتساب) يفتح التقرير
   للاطلاع بلا تسجيل دخول — يعمل فقط بعد الاعتماد.
5. **العميل:** يسجّل دخوله فيرى فقط أجهزته وتقارير زياراته المعتمدة.

## ملاحظات معمارية وأمنية
- **عزل البيانات بين الفروع/العملاء** مطبَّق بالكامل عبر سياسات RLS في
  `schema.sql`، وليس شرطاً في كود الواجهة — حتى لو عُدِّل `index.html` لا
  يمكن لمستخدم رؤية بيانات فرع/عميل آخر.
- **حاوية الصور `ppm-photos` للقراءة العامة** عمداً (بلا تسجيل دخول)، لأن
  ميزة "رابط المشاركة عبر واتساب" تحتاج عرض صور التقرير لمن لا حساب له.
  الكتابة/الحذف تبقى مقصورة على المستخدمين المسجّلين وفق فرعهم/عملائهم عبر
  دالة `can_access_client`. إن كانت خصوصية الصور حرجة لاحقاً، يمكن استبدال
  هذا برابط تحميل موقّع (Signed URL) عبر Edge Function.
- **ضغط الصور** يتم بالكامل في متصفح الفني قبل الرفع (تصغير لأطول ضلع
  ١٦٠٠px بجودة ٠٫٧) كما في المواصفة — بذلك يكون حجم كل صورة ١٥٠–٢٥٠ كيلوبايت.
- **رابط المشاركة العام** يمر عبر دالة قاعدة بيانات واحدة
  (`rpc_public_report`) بدل فتح سياسات RLS عامة، فلا يكشف إلا الزيارة
  المعتمدة صاحبة الرمز السري (`share_token`) فقط.
- **حسابات الفنيين/العملاء** تُنشأ من لوحة Supabase مباشرة (لا حاجة لمفتاح
  Service Role داخل متصفح عام)، ثم تُستكمل بياناتها (الاسم، الدور، الفرع،
  ربط العميل) من داخل شاشة "إدارة المستخدمين" في النظام.

## التكلفة المتوقعة (كما في المواصفة)
الباقة المجانية في Supabase (١ جيجابايت تخزين) تكفي نحو سنة تشغيل بمعدل
١٠٠–٥٠٠ صورة مضغوطة شهرياً. بعدها: ترقية ٢٥ دولاراً/شهرياً (١٠٠ جيجابايت)،
أو أرشفة صور السنوات السابقة خارج النظام. Netlify يبقى مجانياً دائماً بهذا
الاستخدام.

## المطلوب منك لتشغيل عميل تجريبي
راجع قسم "١١. المطلوب منك للبدء" في وثيقة المواصفة الأصلية: شعار الشركة،
ملف Excel لأجهزة العميل التجريبي، بيانات العقد، أسماء/بريد الفنيين، واسم
العميل بالعربية والإنجليزية.
